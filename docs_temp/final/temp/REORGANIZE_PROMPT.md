# 任务：文档重组

将 `docs_temp/clean/` 下的 8 个文档打散重组为本目录（`docs_temp/refactored/`）下的若干文档。

## 背景

整个平台叫 **neoplatform**（不仅限于 neospace 工作台）。neoplatform 包含：
- **neolyst**：内部管理系统（Next.js + Supabase）
- **neoport**：外部发布系统
- **neoskills**：业务逻辑库（Agent Skills）
- **neospace**：AI 工作台

`docs_temp/clean/` 下的 8 个文件是历史积累的文档，存在大量交叉重复。需要打散按主题重组，每个新文件回答一类问题。

## 工作方式

开始前先调用 `/document-skills:doc-coauthoring` skill，按其协作写作流程执行。

## 写作清理

写完每个文件后，用 `elements-of-style:writing-clearly-and-concisely` skill 对全文做一轮清理。

写中文。简洁明确，不浮夸。

**原子化 bullet 原则**：尽量拆成 bullet list，每行是一个完整且全局无重复的事实点。每个 bullet 只说一件事，不在多个文件中重复同一事实。这样方便后续进一步整理和搬运。

## 分类方式

先通读全部 8 个源文件，按主题出分类计划，每个文件回答一类问题。分类完成后列出文件清单及每个文件的定位，确认后再动手写。

temp.md 作为固定规则：归属不确定的内容统一放 `temp.md`。

## 约束

- **不要丢失任何信息**。每个事实、规则、约束、代码片段都必须出现在某个新文件中
- **不要标注来源**（不写"来自 ARCHITECTURE.md"之类的引用）
- **不要添加新内容**。只做重组和精简
- **可能过时的内容也先整理进去**，不加"可能过时"标记
- **归属不确定的内容放 temp.md**
- 文件内不要出现对本次被重组的源文件的引用（如"见 ARCHITECTURE.md"），新文件之间的交叉引用可以用
- **涉及数据库的内容（表结构、字段类型、外键、约束、RLS 矖阵、存储路径命名等），提取其中蕴含的业务含义和规则单独整理到对应文件，删掉数据库实现细节**（如 uuid 主键、timestamptz、ON DELETE 语义、字段类型等）。业务规则保留，数据库机制删除。

## 最后：完整性检查

全部 6 个文件写完后，执行以下检查确保无内容丢失：

1. **逐文件比对**：将 8 个源文件逐个过一遍，确认每个事实点（表格、规则、约束、流程步骤、代码片段、命名规范）在新文件中有对应
2. **列出清单**：输出一个检查报告，按源文件分组列出"已覆盖 ✅"和"遗漏 ❌"
3. 如果发现遗漏，立即补充到对应文件
4. 检查 temp.md 是否有应该归入正式文件的内容被错误放入
