# 分析师投研报告平台 Overview

## 1. 概述

### 1.1 核心目标

AI 驱动的研报生产力提升，围绕四个方向：

- **业务主导的自我进化**：Editor 和 SA 通过自然语言对话沉淀业务规则（Skills），无需研发介入即可配置工作流、修改提取规则、优化审核逻辑。
- **全自动报告生产**：AI 学习历史报告样本构建排版模板，自动解析草稿要素并秒级排版，消除人工调整格式的负担。
- **合规风险自动拦截**：机器初筛 SFC 牌照、Stock List、利益披露、评级变动等合规项，高亮风险点，降低人为疏漏。
- **角色转型**：从"操作者"转向"监督者"。人工负责制定规则、监督生产过程、确认最终结果。

### 1.2 业务角色

| 角色 | 职责 | 交互方式 |
|------|------|----------|
| Analyst（分析师） | 提交草稿和指令 | 微信；后期直连 AI Agent |
| Editor | 处理任务，维护系统规则 | 工作台 |
| SA（审批/合规） | 审批和发布报告 | 工作台 |
| Admin | 管理用户权限、行业分类等 | 工作台 |
| 外部投资者 | 查看发布报告 | 外部发布系统 |

## 2. 平台架构

```
[分析师] => [企业微信] => [Editor 工作台] => [Neolyst-db] => [Neoport-db]
                             (解析排版)        (内部数据中心)    (对外发布库)
                                                  ^
                                                  |
[SA 审批] => [SA 工作台] ─────────────────────────┘
              (合规检查/审批)

[Neolyst-web] ──> [Neolyst-db]    [Neoport-web] ──> [Neoport-db]
(内部查询/审计)                    (外部查阅/渠道)
```

各模块职责：

| 模块 | 职责 |
|------|------|
| 企业微信 | 前端入口，收发文件和指令 |
| Editor 工作台 | 解析草稿、提取数据、自动排版，结果写入 neolyst-db |
| SA 工作台 | 合规检查，审批后修改 neolyst-db 状态为"已发布" |
| 独立发布进程 | 监听"已发布"状态变更，同步文件和数据到 neoport-db |
| Neolyst-db | 内部数据库，存人员、权限、报告版本和操作日志 |
| Neoport-db | 外部数据库，只存发布给客户的最终版报告 |

## 3. 核心机制

### 3.1 权限管控与审计分离

- **实名登录与写库**：所有人员使用专属实名账号登录工作台，操作记录写入审计日志。
- **代建放行与归属解耦**：Editor 可代理分析师创建报告。审计日志记录"真实操作人 (Editor)"，业务上报告归属"Analyst"。

### 3.2 渐进式自动化

- **人机协作**：系统处理标准提取、排版与合规工作；特例由人工兜底。
- **经验固化**：人工兜底后，通过自然语言对话将经验转化为新的自动化规则（Skills）。

## 4. 核心工作流

### 4.1 报告生产

1. 分析师通过微信发送草稿与指令。
2. Editor 登录工作台，指定归属分析师，调用自动化技能。
3. 系统解析并排版。Editor 核对后确认，系统以 Editor 身份写入 neolyst-db，状态标记为"待审核"。

### 4.2 审批发布

1. SA 登录工作台调用审核功能，系统高亮合规风险点。
2. SA 确认后下达发布指令。
3. 系统修改 neolyst-db 状态为"已发布"，独立进程侦测后同步至 neoport-db。

## 5. 代码库划分

| 仓库 | 内容 |
|------|------|
| neolyst | 内部管理系统（neolyst-web + neolyst-db 物理模型） |
| neoport | 外部发布系统（neoport-web + neoport-db + Publish Worker） |
| neoskills | 业务逻辑库（解析、提取、排版、模板生成、合规检查）。内部按 `skills/`（Agent Skills 插件）、`templates/`（正式模板）、`reports/`（报告处理现场）组织 |
| neospace | 工作台（Skills 运行载体，编排业务流程） |

## 6. 技术栈

| 层面 | 技术 |
|------|------|
| 数据与权限 | Supabase（PostgreSQL + RLS + Storage） |
| 前端 | Next.js（App Router） |
| 业务逻辑 | Python（文档处理、数据解析、图表生成） |
| 部署 | 初期用 opencode 挂载 GitHub 仓库；后期部署自研容器化工作台 |

## 7. 实施规划

### 7.1 第一阶段：业务启动 (MVP)

解决排版工作量最大的问题。用 opencode 挂载技能库，Editor 通过对话调用 `template_maker` 和 `report_maker` 完成模板制作、字段维护和报告排版。第一版保留 Word 片段拼装，不引入 Markdown 中间层。

### 7.2 第二阶段：工作台成型

上线 neospace，覆盖翻译、刷新、合规等全部自动化技能。Editor 继续负责规则固化和业务流程串联。

### 7.3 第三阶段：分析师直连

系统直接对接微信。分析师发报告，系统自动处理并推给 SA。标准报告不再需要 Editor 介入，Editor 转型为系统监督者。
