# 文档组织原则

从文档整理实践中总结。

## 分层：通用 vs 特有

跨项目复用的规则放 `docs/principles/`，项目特有的操作放项目目录下。判断标准：换一个项目，这条规则还成立吗？

## 单一来源

每个知识点只在一个文件里写，其他地方只放链接。改规则只改一个地方。

## 就近

文档跟着它描述的对象走。推送脚本的说明跟着脚本走，不会放在无关目录下。

## 一个文件一个关注点

不要在一个文件里塞两个话题。ARCHITECTURE.md 管业务逻辑边界，SUPABASE.md 管数据库规范。

## 删掉没用的

重复文件、空标题、过时内容直接删。不保留历史痕迹做纪念。

## 紧凑

常用操作压缩成表格或单行命令。目录结构和文件说明合并，不拆成两个小节重复列举。
