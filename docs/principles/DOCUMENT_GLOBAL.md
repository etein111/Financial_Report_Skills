# 全局文档 STANDARD

## 什么是全局文档

全局文档保存项目或子系统级别的整体规则——包括整体职责边界、跨模块共享规则和核心模型。这些规则在代码演进、目录调整、模块重拆后仍然成立，除非项目方向或系统设计本身发生变化。全局文档服务于长期一致性，而非局部实现说明。

## 判断口径

- 描述整体规则，而非局部实现
- 同时约束多个模块或接口
- 代码重构后通常仍成立
- 主要作用是统一认知，而非指导单点调用

## 典型内容

- **定位**：系统是什么、为什么存在、承担什么角色
- **目标与范围**：当前阶段要解决的问题和边界
- **关键边界**：系统间及上下游的职责划分
- **生命周期模型**：对象、流程或状态的整体运作方式
- **跨模块共享语义**：多模块共同依赖的概念、字段、状态、标识规则
- **跨接口共享规则**：整个能力面共同遵守的规则
- **架构原则**：职责落点、数据真相位置、分层原则等设计总则
- **关键约束**：安全、权限、外部平台、数据、兼容性等长期约束
- **长期开放问题**：尚未收口但影响整体设计的问题
