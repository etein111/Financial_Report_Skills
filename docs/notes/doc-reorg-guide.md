# 文档整理搬迁指南

## 前置准备

开始整理前，先加载两个 skill：

1. **doc-coauthoring**（`/document-skills:doc-coauthoring`）

2. **elements-of-style**（`/elements-of-style:writing-clearly-and-concisely`）
   写入目标文档的文案时应用

## 交互流程

1. **读取全貌**
   先读源文档和所有可能的目标文档，了解当前状态。

2. **拆段展示**
   把源文档按逻辑段落拆分，列出结构表（段落、行号、概要）。

3. **逐段处理**
   对每段内容：
   - 给出归属建议（哪个文档、哪个节）
   - 说明理由
   - 用户确认后执行（写入目标、删除原文）
   - 确认一段再处理下一段，不一起搞

4. **混合内容逐条过滤**
   当一段内容混杂了业务规则和实现细节：
   - 逐条列出判断（保留/删除/提炼语义）
   - 用户确认过滤结果
   - 再给出最终归属表（只列要做的）
   - 用户确认后再执行

5. **概念不清时先调查**
   遇到源文档的概念模型可能有误：
   - 停下来查权威源（seed 数据、代码等）
   - 把事实呈现给用户
   - 用户确认正确模型后再整理

6. **不确定归属时先讨论**
   内容不属于任何现有文档时：
   - 列出可选归属及取舍
   - 给出推荐方案
   - 用户决定后再处理

7. **每次搬迁后审核**
   一个文档处理完毕后，审核所有修改：
   - 检查格式一致性
   - 检查节顺序
   - 检查冗余和遗漏
   - 用户确认后再处理下一个
