# Superpowers 项目技术文档

## 一、项目概述

### 1.1 项目定位

**Superpowers** 是一个面向AI编程代理的**技能框架（Agentic Skills Framework）**与**软件开发方法论**，由 Jesse Vincent（著名开源开发者，Git/Sequel著名项目维护者）创建，现由 Prime Radiant 团队维护。

该项目的核心理念是：**不让AI直接写代码，而是让AI先理解需求、制定计划、通过子代理分工执行，并在整个过程中遵循严格的工程纪律**。

> **项目数据**：⭐ 99.9k Stars | 8k Forks | 389 Commits | 27 Contributors

### 1.2 核心价值

| 特性 | 描述 |
|------|------|
| **自动化工作流** | 技能自动触发，无需人工干预 |
| **工程纪律** | 强制 TDD、系统化调试、代码审查 |
| **子代理协作** | 任务分发 + 两阶段评审机制 |
| **多平台支持** | Claude Code、Cursor、Codex、OpenCode、Gemini CLI |

### 3.2 关键技能详解

#### 3.2.1 Test-Driven Development (TDD)

**铁律**：`无测试，不编码`

```
RED → Verify RED → GREEN → Verify GREEN → REFACTOR → Next
```

**核心原则**：
- 必须先写失败测试，再写实现代码
- 写最简代码通过测试
- 写测试前先删除已写的代码
- 测试必须验证真实行为（不用mock除非不可避免）

**红牌警告（立即停止并重写）**：
- 代码写于测试之前
- 测试立即通过
- 无法解释测试为何失败
- "这次例外"思维

#### 3.2.2 Subagent-Driven Development

**两阶段评审机制**：

```
任务分发 → 实现 → 规范合规审查 → 代码质量审查 → 下一个任务
              ↓                  ↓
         修复不合规项        修复质量问题
              ↓                  ↓
           再审查              再审查
```

**模型选择策略**：
| 任务类型 | 模型选择 |
|---------|---------|
| 机械实现（1-2文件，明确规格）| 快速便宜模型 |
| 集成判断（多文件，复杂协调）| 标准模型 |
| 架构设计审查 | 最强模型 |

#### 3.2.3 Systematic Debugging

**四阶段流程**：

```
Phase 1: 根因调查 ──→ Phase 2: 模式分析 ──→ Phase 3: 假设验证 ──→ Phase 4: 修复实现
   │                         │                       │                      │
   ▼                         ▼                       ▼                      ▼
读错误信息                  找类似代码               形成单一假设            创建失败测试用例
复现问题                    对比参考实现             最小化测试             修复根因
检查变更                    识别差异                 验证                   验证修复
追踪数据流                  理解依赖
```

**3次修复失败 = 架构问题**：停止修复，讨论根本架构是否合理

### 4.1 支持平台

安装完成后，新会话中提问触发技能：
- "help me plan this feature"
- "let's debug this issue"

Agent 应自动调用相关 Superpowers 技能。

## 五、优势分析

### 5.1 核心优势

| 优势 | 说明 |
|------|------|
| **工程纪律保障** | 强制 TDD、禁止猜测式修复，确保代码质量 |
| **自动化工作流** | 技能自动触发，不依赖人工调用 |
| **子代理高效协作** | 隔离上下文 + 两阶段评审，平衡速度与质量 |
| **可扩展技能体系** | 标准化 SKILL.md 格式，易于贡献新技能 |
| **多平台兼容** | 主流 AI 编码工具均支持 |

### 5.2 设计亮点

1. **"先想后做"范式**：不直接写代码，先理解需求、设计、计划
2. **证据导向**：Verify before completion，避免"感觉修好了"
3. **最小化假设**：子代理获得精确上下文，避免上下文污染
4. **审查闭环**：spec compliance → code quality 双重门禁

## 六、劣势与挑战

| 挑战 | 说明 |
|------|------|
| **学习曲线** | 需要理解完整的技能触发机制和工作流 |
| **初始效率** | 严格流程可能在简单任务上显得繁琐 |
| **平台差异** | 不同 AI 平台的插件机制不同，可能需要调整 |
| **模型依赖** | 子代理驱动依赖模型能力，极端任务可能失败 |
| **上下文限制** | 长对话中上下文可能稀释技能触发效果 |

## 七、应用场景

### 7.1 最佳适用场景

| 场景 | 为什么适合 |
|------|-----------|
| **企业级软件开发** | 需要严格工程纪律和可审计流程 |
| **多人协作项目** | 子代理分工 + 代码审查确保一致性 |
| **复杂系统开发** | 系统化调试 + 分层设计降低风险 |
| **AI 辅助编程团队** | 规范 AI 行为，减少"幻觉"代码 |
| **开源项目维护** | 自动化工作流提高维护效率 |

### 7.2 不适用场景

- 快速原型探索（流程过于严格）
- 一次性脚本/工具（验证开销不成比例）
- 简单 Bug 修复（可能过度工程）

## 九、总结

Superpowers 是 **AI 辅助编程领域的工程化实践框架**。它不是简单的提示词集合，而是一套完整的**软件开发方法论**，核心价值在于：

> **将人类软件工程的最佳实践（TDD、系统化调试、代码审查）转化为 AI 可遵循的自动化流程。**

对于追求代码质量、需要在团队中规模化使用 AI 编程工具的组织和个人，Superpowers 提供了一套经过验证的、可落地的解决方案。
