# README

## 1. 这个标准是针对谁的

本标准针对子系统的维护者、接手者和阅读目录的人。

它服务于这样的场景：

- 第一次进入一个子系统，需要快速知道这块代码是怎么组织的
- 准备修改某个能力，但还没有定位到具体函数，需要先理解模块分工
- 需要运行、调试或联调这个子系统
- 需要判断某段逻辑大致应该落在哪个模块

README.md 不是给单个函数的修改者写的局部说明，也不是用来保存长期稳定的全局规则。

## 2. 基本原则

- 只写子系统级、跨文件、跨模块的说明
- 只写脱离目录地图就不容易快速看懂的内容
- 主要作用是帮助人理解“这块代码怎么分、怎么连、怎么用”
- 内容应在单个函数重写后通常仍然成立
- 不写单个函数的具体执行步骤
- 不写接口字段表、返回值表这类紧贴实现或契约的细节
- 不复述全局文档已经定义的长期规则，只写本子系统内部的落位和组织方式

## 3. 具体都放什么内容

- 子系统的职责概述：这一块代码在项目里承担什么工作
- 目录结构：主要目录和文件各自负责什么
- 模块地图：每个模块的职责边界
- 模块依赖关系：哪些模块可以依赖哪些模块，依赖方向怎么保持清晰
- 核心执行链路：一个能力通常经过哪些模块，但只写模块级流转，不写函数级步骤
- 入口说明：从哪里开始读代码、从哪里进入主要能力
- 运行说明：本目录如何运行、调试、联调、测试
- 配置说明：本目录下配置文件、状态文件、本地文件各自的用途
- 环境约定：环境变量覆盖规则、本地与测试环境的切换方式
- 本地维护约定：哪些文件提交版本库，哪些只在本地存在
- 子系统内部的局部设计机制：例如模块如何分责、校验与提交如何分离、上传与持久化如何分层
- 代码阅读指引：修改某类问题时应优先看哪些模块
