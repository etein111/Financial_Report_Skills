# 架构规范

# Supabase

## 业务逻辑在服务端

- 所有业务逻辑必须在 Supabase侧用Supabase 函数或 RPC 中实现，比如：路径生成规则、字段计算、一致性校验、状态流转。
- 客户端不得硬编码业务逻辑，只做 I/O，包括文件上传、参数整理和接口调用。
- 当操作只包含直接读取且不包含业务逻辑时，才可直接查表。
- 当操作包含业务逻辑时，必须走 RPC。

## 数据库设计
- 原则上尽量不用外键，跨表一致性由 RPC 负责。
- 数据库层面，面向人的文本（错误消息、对象说明、注释）用中文，面向机器的标识符用英文。

## 唯一事实源
- 所有 schema 变更，包括函数、触发器和 RPC，必须写入 `supabase/migrations/` 文件。
- 迁移文件只追加，不修改；已提交的迁移文件不可编辑，所有变更通过新建迁移文件实现。
- `create or replace` 覆盖函数时以数据库当前版本为准，不从旧迁移复制文本。
