# 架构规范

## 数据库

- 业务逻辑必须在服务端实现（函数、RPC、触发器），包括路径生成规则、字段计算、一致性校验、状态流转。
- 客户端不得硬编码业务逻辑，只做 I/O：文件上传、参数整理和接口调用。
- 只读且不含业务逻辑的操作可直接查表；包含业务逻辑的操作必须走 RPC。
- 原则上不用外键，跨表一致性由 RPC 负责。
- 面向人的文本（错误消息、对象说明、注释）用中文，面向机器的标识符用英文。
- 迁移文件只追加，不修改；已提交的迁移文件不可编辑，所有变更通过新建迁移文件实现。
- `create or replace` 覆盖函数时以数据库当前版本为准，不从旧迁移复制文本。

## Supabase

- 所有 schema 变更，包括函数、触发器和 RPC，必须写入 `supabase/migrations/` 文件。
- 迁移文件必须用 `supabase migration new <name>` 创建，不手动拼时间戳。
- 环境管理和本地开发操作见 [supabase/SUPABASE_STANDARDS.md](../supabase/SUPABASE_STANDARDS.md)。
