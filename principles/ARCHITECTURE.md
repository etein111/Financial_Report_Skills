# 架构规范

## 数据库

- 业务逻辑必须在服务端实现（函数、RPC、触发器），包括路径生成规则、字段计算、一致性校验、状态流转。
- 客户端不得硬编码业务逻辑，只做 I/O：文件上传、参数整理和接口调用。
- 纯读操作可由 Python 侧直接查表，前提是同时满足以下三个条件：
  - 单表、按主键或唯一索引查询（不用组合条件拼 ID）
  - 不校验业务状态（不判断存在性、is_active、是否已发布等）
  - 不做字段转换或组合（不 lower/btrim，不拼组合键）
- 不满足上述任一条件的读操作必须走 RPC。
- 包含业务逻辑的写操作必须走 RPC。
- 原则上不用外键，跨表一致性由 RPC 负责。

## 语言

- 面向人的文本（错误消息、对象说明、注释）用中文，面向机器的标识符用英文。
