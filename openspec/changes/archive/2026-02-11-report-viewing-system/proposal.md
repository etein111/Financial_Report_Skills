## Why

当前报告管理系统只提供了内部管理功能，没有为最终用户提供查看报告的界面。需要建立一个独立的报告查看系统，让授权用户（Analyst 和 Admin）能够方便地查看已发布的报告，同时通过自动化 Job 将报告外发给订阅用户。

## What Changes

构建一个独立的报告查看系统，包括:

**用户和认证管理:**
- 独立的用户系统（与报告管理系统的 Auth 隔离）
- 两种角色: Analyst（分析师）、Admin（系统管理员）
- 角色权限控制:
  - Analyst: 只能查看自己的报告
  - Admin: 可以查看所有报告
- 基于 Supabase Auth 的用户认证

**报告查看功能:**
- 用户登录后查看报告列表
- 点击报告查看详情（基本信息 + 下载文件）
- 报告数据来源于报告管理系统的已发布报告

**报告接收功能:**
- 提供 API 接收来自其他系统发布的报告（报告信息 + 附件文件）
- 接收后自动存储到本地数据库和文件系统
- 支持增量同步（按时间戳查询）

**报告外发功能:**
- 外发邮箱配置管理（SMTP 服务器设置：host、port、username、password 等）
- 用户订阅管理（订阅的用户能收到所有已发布报告）
- Job 定时任务执行报告外发
- 发送记录监控（记录每次发送状态：成功/失败、失败原因、重试次数）
- 本版本支持邮件外发
- 预留扩展：后续版本支持 FTP 和 API 外发

## Capabilities

### New Capabilities
- `用户认证`: 基于 Supabase Auth 的用户登录系统
- `报告接收`: 提供 API 接收外部系统发布的报告（信息 + 附件）
- `报告列表查看`: 根据用户角色显示报告列表（Analyst 只看自己的，Admin 看所有）
- `报告详情查看`: 查看报告完整信息并下载附件
- `邮件外发`: 邮箱配置管理 + 用户订阅管理 + Job 定时发送 + 发送记录监控
- `权限隔离`: 基于角色的报告访问控制

## Impact

**数据库结构:**
- 新增 User 表（报告查看系统用户）
- 新增 EmailConfig 表（外发邮箱配置：SMTP 设置）
- 新增 Subscription 表（用户订阅配置：订阅邮箱，订阅类型包含普通用户订阅、Wind订阅、同花顺订阅 后续可能会新增新的类型）
- 新增 Report 表（报告基本信息）
- 新增 ReportFile 表（报告附件）
- 新增 DistributionLog 表（报告外发记录：状态、失败原因、重试次数）

**后端 API:**
- FastAPI 服务，提供用户认证、报告查询的 RESTful API
- 报告接收 API（供外部系统推送报告）
- 邮箱配置管理 API（Admin 专用）
- 用户订阅管理 API（Admin 专用）
- 发送记录查询 API（Admin 专用）
- 集成 Supabase 认证
- Job 调度系统（使用 Prefect 或类似工具）
- 邮件发送功能

**前端界面:**
- Vue 3 单页应用
- 登录页面 : 参照./prototype下面login.html原型设计
- 报告列表页面 : 参照./prototype下面reports.html原型设计
- 报告详情页面
- Admin 管理页面：邮箱配置、用户订阅管理、发送记录查看
- 界面语言: 英文

**外部依赖:**
- SMTP 服务器（邮件外发）
