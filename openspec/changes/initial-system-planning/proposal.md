## Why

建立一个集中化的系统来管理报告的创建、编辑、版本控制、审核和发布流程，支持多角色权限管理和工作流审批。

## What Changes

构建一个基于 Web 的投资研究报告管理系统(第一个版本),包括:

**用户和权限管理:**
- 三种角色: Analyst(分析师)、SA(合规人员)、Admin(系统管理员)
- 角色权限控制:
  - Analyst: 只能查看和编辑自己的报告
  - SA: 可以查看所有人的报告，负责审核，但不能创建或编辑报告
  - Admin: 拥有所有权限，可以查看和编辑所有报告，可以替分析师创建报告
- 添加分析师时自动创建 Supabase Auth 账号

**基础数据管理模块:**
- Analyst(分析师)信息管理
- Coverage(公司覆盖)信息管理
- Sector(行业分类)管理(两级结构)
- Region(地区)管理
- 报告模板文件管理(Word/Excel)

**报告管理模块:**
- 报告创建(基本信息 + Word 文档 + Excel 模型文件)
  - Admin 可以替分析师创建报告(需要选择创建给哪个分析师)
  - Analyst 只能创建自己的报告
  - SA 不能创建报告
- 报告编辑(基本信息和文件)
- 版本管理(任何对报告的修改都保留历史：基本信息、Word文档、Excel模型文件，记录修改人和时间)
- 报告状态流转: 草稿 → 已提交 → (已发布/已拒绝)
  - 草稿(draft): 报告初始状态，可编辑
  - 已提交(submitted): 分析师提交审核，等待 SA 审批，Analyst 仍可继续编辑
  - 已发布(published): SA 批准发布
  - 已拒绝(rejected): SA 拒绝发布

**报告审核模块:**
- SA 专属功能: 查看所有已提交的报告
- 审核操作: 批准发布、拒绝发布
- 审核历史: 记录审核人和审核时间

**对外接口:**
- 提供已发布报告的查询 API,支持按时间戳增量查询
- 报告查看网站是独立系统,由其他项目负责
- 本系统只提供接口供其获取已发布报告

## Capabilities

### New Capabilities
- `用户权限管理`: 基于角色的访问控制(RBAC)，三种角色权限
- `基础数据管理`: 管理分析师、公司覆盖、行业分类、地区等基础数据
- `报告创建`: 创建新的研究报告,关联基础数据和上传文件
  - Admin 可代 Analyst 创建
  - 添加 Analyst 时自动创建账号
- `报告编辑`: 修改报告基本信息和文件
- `版本管理`: 任何修改(基本信息/Word文档/Excel模型文件)都保留版本历史,记录修改人和修改时间,支持合规检查
- `报告工作流`: 草稿 → 已提交 → 已发布/已拒绝的状态流转
- `报告审核`: SA 专属功能，审批或拒绝已提交的报告
- `权限隔离`: Analyst 只能查看自己的报告，SA 和 Admin 可查看所有报告

## Impact

**数据库结构:**
- 新增 Analyst、Coverage、Sector、Region 表
- 新增 Template 表(报告模板 Word/Excel)
- 新增 Report、ReportVersion、ReportFile 表

**后端 API:**
- FastAPI 服务,提供基础数据和报告管理的 RESTful API
- 集成 Supabase 认证和存储

**开发工具:**
- 使用 uv 作为统一的包管理和项目工具链
- 后端 Python 项目使用 uv 管理依赖、虚拟环境和脚本运行
- 提供极致的依赖安装和脚本执行速度

**前端界面:**
- Vue 多页面应用，采用桌面式界面设计
- 界面语言: 英文 (所有 UI 文本、标签、按钮均使用英文)
- 桌面环境: 功能卡片分组显示(报告功能组 + 基础数据管理组)
- 功能页面: 每个功能在新标签页打开，独立 URL
- 报告管理页面: 报告列表、创建报告、编辑报告、报告模板管理
- 基础数据管理页面: Analyst、Coverage、Sector、Region 管理
- 数据内容: 支持中文(报告标题、摘要、分析师姓名等业务数据可使用中文)
