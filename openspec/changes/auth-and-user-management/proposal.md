## Why

建立系统的基础权限和用户管理设施，为后续的报告管理功能提供安全的认证和授权基础。通过实现登录界面、权限控制、用户管理、Region 管理、Analyst 信息管理，让系统具备基本的访问控制和多角色支持。

## Scope

**包含的功能：**
- 用户认证系统（登录、登出、Token 验证）
- 基于角色的权限控制（Admin、SA、Analyst）
- **用户管理**（管理所有 Auth 用户，包括创建、编辑、删除、修改密码、修改角色）
- 基础数据管理（Region、Analyst信息的 CRUD）
- 密码管理（Admin 直接修改用户密码、用户自助通过邮件重置密码）
- 用户界面（登录页、桌面主页、管理页面）

**不包含的功能：**
- 其他基础数据管理（Sector、Coverage、Template）
- 报告相关功能（包括报告审核，这是 SA 角色在后续变更中的主要用途）

**角色说明：**
- **Admin** - 系统管理员，在当前变更中拥有所有权限
- **SA (Senior Analyst)** - 高级分析师，在当前变更中与 Analyst 权限相同，预留用于未来的报告审核功能
- **Analyst** - 普通分析师，在当前变更中与 SA 权限相同

## Features

### Feature 1: 用户登录和身份验证

**用户价值：** 用户可以安全登录系统，系统自动验证身份并在会话中保持登录状态。

**用户故事：**
- 作为系统用户，我需要使用邮箱和密码登录
- 作为系统用户，我需要登录后能够访问系统功能，无需重复登录
- 作为系统用户，我需要能够登出系统
- 作为系统管理员，我需要能够初始化第一个 Admin 账号
- 作为用户，我可以通过"忘记密码"功能自助重置密码（通过邮件验证）

**功能点：**
- 登录表单（邮箱 + 密码 + 登录按钮）
- 登录失败时显示错误提示
- 登录成功后跳转到桌面主页
- 登出功能，点击后返回登录页
- "忘记密码"链接，点击后可输入注册邮箱
- 系统发送重置密码邮件到注册邮箱
- 邮件包含一次性重置链接
- 用户点击链接后可设置新密码
- 密码重置成功后可用新密码登录
- 登录页视觉设计（粒子背景效果）
- **副标题**：在登录框中显示 "Research Report Management System"
- Admin 账号初始化（首次部署时创建默认管理员）

### Feature 2: 角色权限控制

**用户价值：** 系统根据用户角色控制访问权限，确保数据安全和职责分离。

**角色定义：**
- **Admin** - 系统管理员，拥有所有权限
- **SA** (Senior Analyst) - 高级分析师，在当前变更中与 Analyst 权限相同，预留用于未来的报告审核功能
- **Analyst** - 普通分析师，在当前变更中与 SA 权限相同

**功能点：**
- 不同角色登录后看到的功能不同
- 未登录用户访问受保护页面时自动跳转到登录页
- 无权限访问的功能/按钮不显示或禁用

**权限规则：**
| 功能 | Admin | SA | Analyst |
|------|-------|-------|---------|
| 查看/管理 Region | ✅ | ❌ | ❌ |
| 查看/管理 Analyst | ✅ | ❌ | ❌ |
| 修改用户密码 | ✅ | ❌ | ❌ |

### Feature 4: 用户管理

**用户价值：** Admin 可以管理系统中的所有用户账号，控制访问权限和角色分配。

**用户故事：**
- 作为 Admin，我需要查看所有用户列表（Admin、SA、Analyst）
- 作为 Admin，我需要创建新用户账号
- 作为 Admin，我需要编辑用户信息（姓名、邮箱）
- 作为 Admin，我需要直接修改任何用户的密码
- 作为 Admin，我需要修改用户的角色（在 Admin、SA、Analyst 之间切换）
- 作为 Admin，我需要删除用户账号
- 作为 Admin，我需要启用/禁用用户账号

**功能点：**
- 用户列表（表格形式展示，支持按姓名或邮箱搜索）
- 创建用户（输入姓名、邮箱、选择角色、设置初始密码）
- 编辑用户信息
- 直接修改密码（在管理页面输入新密码，立即生效）
- 修改用户角色（下拉选择：Admin、SA、Analyst）
- 删除用户（删除前需要确认）
- 启用/禁用用户账号
- 创建时检查邮箱是否已存在
- 权限控制：仅 Admin 可访问和管理

**用户数据字段：**
- 姓名 - 用户显示名称
- 邮箱 - 登录账号（唯一）
- 角色 - Admin/SA/Analyst

**权限规则：**
| 操作 | Admin | SA | Analyst |
|------|-------|-------|---------|
| 查看列表 | ✅ | ❌ | ❌ |
| 创建用户 | ✅ | ❌ | ❌ |
| 编辑用户 | ✅ | ❌ | ❌ |
| 修改密码 | ✅ | ❌ | ❌ |
| 修改角色 | ✅ | ❌ | ❌ |
| 删除用户 | ✅ | ❌ | ❌ |
| 启用/禁用 | ✅ | ❌ | ❌ |

**用户操作流程：**

*创建用户：*
1. Admin 填写表单并提交（姓名、邮箱、角色、初始密码）
2. 系统创建用户账号
3. 告知用户账号信息
4. 用户首次登录后可自行修改密码

*修改角色：*
1. Admin 在用户列表中找到目标用户
2. 点击"修改角色"按钮
3. 在下拉菜单中选择新角色（Admin/SA/Analyst）
4. 系统更新角色并提示成功
5. 用户下次登录时新角色生效

- 作为 Admin，我需要创建新的地区

**功能点：**

- 权限控制：仅 Admin 可访问和管理

### Feature 6: Analyst信息管理

**用户价值：** Admin 可以管理分析师的业务信息信息（姓名、地区、SFC 编号等），与用户账号系统解耦。

**用户故事：**
- 作为 Admin，我需要查看所有分析师的业务信息
- 作为 Admin，我需要创建新的业务信息（无需创建用户账号）
- 作为 Admin，我需要编辑业务信息信息
- 作为 Admin，我需要删除不需要的业务信息

**功能点：**
- 业务信息列表（表格形式展示，支持按姓名或邮箱搜索）
- 创建业务信息（填写：英文姓名、中文姓名、邮箱、后缀、所属地区、SFC 编号）
- 编辑业务信息信息
- 删除业务信息（删除前需要确认）
- 表单验证（英文姓名、邮箱必填，邮箱唯一）
- 权限控制：仅 Admin 可访问和管理

**权限规则：**
| 操作 | Admin | SA | Analyst |
|------|-------|-------|---------|
| 查看列表 | ✅ | ❌ | ❌ |
| 创建 | ✅ | ❌ | ❌ |
| 编辑 | ✅ | ❌ | ❌ |
| 删除 | ✅ | ❌ | ❌ |

**注意：** Analyst信息与用户账号系统完全解耦：
- 创建业务信息不自动创建用户账号
- 删除业务信息不删除用户账号
- 邮箱字段仅用于业务记录，不与认证系统关联

**隐式关联规则（为未来报告功能预留）：**
- 当 User Auth 的 email 与 Analyst 的 email **一致时**，系统认为是**同一人**
- **当前阶段：** 只有 Admin 可以访问业务信息管理，SA/Analyst 不需要
- **未来报告功能：** Analyst 登录后可以查看/编辑自己的报告（报告表的 `contact_person` 字段关联到 analyst.email）
- **不使用外键关联**，通过 email 字符串匹配实现逻辑关联
- 示例：Analyst `john.doe@example.com` 登录后，只能看到 `contact_person = 'john.doe@example.com'` 的报告

## System Impact

**数据库层：**
- 新增 `region` 表（地区数据），RLS policies：仅 Admin 可读写
- 新增 `analyst` 表（Analyst信息，与用户账号解耦），RLS policies：仅 Admin 可读写
- 新增 RLS 辅助函数 `get_current_role()`
- 用户账号由 Supabase Auth 管理（不在这个变更的数据库中）

**后端 API（FastAPI）：**
- 认证接口：`/api/auth/login`, `/api/auth/logout`, `/api/auth/me`
- 密码重置接口：`/api/auth/forgot-password`, `/api/auth/reset-password`, `/api/auth/change-password`
- 用户管理 API：`/api/users` (CRUD, 修改密码, 修改角色, 启用/禁用)
- Region 管理 API：`/api/regions` (CRUD)
- Analyst信息 API：`/api/analyst-info` (CRUD)
- JWT 验证中间件
- Supabase Python Client 集成（使用 Admin API 管理用户）

**前端界面（Vue 3）：**
- 登录页面（含粒子背景、忘记密码链接）
- 重置密码页面（通过邮件链接访问）
- 桌面主页（功能卡片 + 导航栏）
- 用户管理页面（仅 Admin）
- Region 管理页面（仅 Admin）
- Analyst信息管理页面（仅 Admin）
- Axios 拦截器（自动添加 Token）
- Vue Router 路由守卫

**开发工具：**
- 初始化脚本 `backend/scripts/init_admin.py`

## Key Decisions

1. **角色存储位置**：用户角色存储在 Supabase Auth 的 `app_metadata` 中（仅服务端可修改），防止用户自行提升权限
2. **用户账号与业务信息分离**：用户账号系统与 Analyst信息系统完全解耦，独立管理
3. **初始化自动化**：使用独立脚本（`backend/scripts/init_admin.py`），自动创建 Admin 用户并配置 JWT 有效期
4. **粒子背景实现**：完全按照设计文档实现（120 个粒子，蓝色-青色渐变，无鼠标交互）
5. **功能卡片显示**：桌面显示所有规划的功能，但只有 Region 和 Analyst 管理可用
6. **功能页面交互方式**：功能卡片点击后在新标签页打开，功能页面无需返回按钮，用户直接关闭标签页返回桌面
7. **密码管理方式**：支持两种方式
   - Admin 在管理页面直接修改用户密码
   - 所有用户可通过登录页"忘记密码"功能自助重置（通过邮件验证）
8. **Token 有效期**：设置为 24 小时（由初始化脚本自动配置），过期后要求用户重新登录，暂不实现 refresh token 机制
